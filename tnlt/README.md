# TNLT Design & Construction Workspace

เว็บแอปสาธิตในเครื่องสำหรับบริษัทออกแบบและรับเหมาก่อสร้าง ใช้ภาษาไทยและเก็บข้อมูลจริงใน SQLite ไม่ใช่หน้า mockup

## เริ่มใช้งาน

ต้องใช้ Node.js รุ่นที่รองรับ Next.js 16 และ npm

```bash
npm install
copy .env.example .env
npm run db:generate
node scripts/prepare-db.mjs
npm run db:push
npm run seed
npm run dev
```

เปิด `http://127.0.0.1:3100`

`seed` ใช้ข้อมูลสาธิตภาษาไทย โดยใช้วันที่ปัจจุบันตามเขตเวลา Asia/Bangkok เพื่อให้มีงานวันนี้ งานใกล้ถึงกำหนด และงานเกินกำหนด การรันซ้ำใช้ `upsert` และไม่ล้างข้อมูลที่ผู้ใช้เพิ่มเอง

คำสั่งตรวจสอบ:

```bash
npm test
npm run typecheck
npm run lint
npm run build
```

## สิ่งที่มีในรุ่นนี้

- Dashboard พร้อมตัวเลขจากฐานข้อมูลจริง กราฟกระแสเงินสด ต้นทุนโครงการ ใบเสนอราคา และภาระงานทีม
- ลูกค้า ใบเสนอราคา ใบพิมพ์ใบเสนอราคา และการอนุมัติแล้วสร้างโครงการโดยไม่สร้างซ้ำ
- โครงการพร้อมภาพรวม แผนงาน เอกสารแบบ รายงานหน้างาน ทีมช่าง ต้นทุน งานเพิ่ม-ลด ตรวจงาน และประกันงาน
- ตารางนัดหมายและแผนงานแบบวัน สัปดาห์ เดือน และรายการ
- คิวทีมช่างพร้อมตรวจช่วงเวลาจองซ้อน
- วัสดุ เครื่องมือ การเคลื่อนไหวสต๊อก ใบขอซื้อ ใบสั่งซื้อ รับของบางส่วน/ครบ และผู้ขาย
- รายรับ รายจ่าย งวดชำระ และรายงานต้นทุน
- อัปโหลดไฟล์ PDF และรูปภาพลง `data/uploads` โดยสร้างชื่อไฟล์ใหม่ ตรวจชนิด/ลายเซ็นไฟล์ และจำกัดขนาด 10 MB
- audit log, request id สำหรับป้องกันการส่งคำสั่งซ้ำ และการยกเลิกรายการแทนการลบประวัติ
- Responsive layout, sidebar ย่อ/ขยาย, mobile menu, keyboard focus และสถานะ loading/empty/error/success

## หลักการเงินและต้นทุน

จำนวนเงินทั้งหมดเก็บเป็นจำนวนเต็มหน่วยสตางค์ใน JSON ของ SQLite และแสดงผลเป็นเงินบาท ตัวอย่าง 100 บาทเก็บเป็น `10000` การคำนวณใบเสนอราคาใช้ยอดรายการหักส่วนลดแล้วคำนวณ VAT และปัดภาษีเป็นสตางค์

- เงินรับจริง = รายการ `income` ที่ยังไม่ถูกยกเลิก
- เงินจ่ายจริง = รายการ `expenses` ที่ยังไม่ถูกยกเลิก
- ต้นทุนวัสดุ = ต้นทุนต่อหน่วยเมื่อเบิกไปโครงการ หักกลับเมื่อคืนของ
- ค่าแรง ผู้รับเหมาช่วง และค่าใช้จ่ายอื่นมาจากรายการรายจ่าย
- รายจ่ายหมวด `วัสดุ (จ่ายซื้อ ไม่คิดต้นทุนซ้ำ)` ไม่ถูกนำมาบวกในต้นทุนโครงการ เพราะวัสดุจะถูกคิดเมื่อเบิกใช้
- มูลค่าสัญญาในรายงานรวมงานเพิ่ม-ลดเฉพาะสถานะอนุมัติ
- การรับเงินผูกกับงวดชำระและไม่ให้รับเกินยอดงวด

การรับของ การโอน/เบิก/คืนวัสดุ และคำสั่งที่เปลี่ยนหลายตารางทำผ่าน Prisma transaction พร้อมตรวจสต๊อกไม่ให้ติดลบ ใบสั่งซื้อป้องกันรับเกินจำนวนสั่ง และใช้ audit log ตรวจสอบย้อนหลัง

## ฐานข้อมูลและสำรองข้อมูล

ฐานข้อมูลเริ่มต้นอยู่ที่ `data/tnlt.db` ตาม `DATABASE_URL` ใน `.env` ไฟล์อัปโหลดอยู่ที่ `data/uploads` ทั้งสองส่วนควรสำรองพร้อมกัน เช่น หยุด dev server ก่อน แล้วคัดลอกสองรายการไปยังพื้นที่สำรองที่ปลอดภัย การกู้คืนให้คืนไฟล์แล้วรัน `npm run db:generate` หากมีการเปลี่ยน schema

ไม่ควร commit `.env`, ฐานข้อมูล หรือไฟล์แนบ เพราะถูกยกเว้นไว้ใน `.gitignore`

## ข้อจำกัดก่อนใช้งานจริง

- รุ่นนี้เป็นระบบสาธิตผู้ใช้คนเดียวในเครื่อง ยังไม่มีการยืนยันตัวตน session, การกำหนดสิทธิ์จริง, CSRF protection ระดับ production หรือการแยกข้อมูลหลายบริษัท
- บทบาทสมาชิกทีมเป็นข้อมูลอ้างอิงเท่านั้น ไม่ได้บังคับสิทธิ์
- ไฟล์แนบเก็บใน local filesystem ยังไม่มี object storage, virus scanning, retention policy หรือระบบสำรองอัตโนมัติ
- ก่อนนำขึ้นใช้งานจริงควรเพิ่ม authentication/authorization, HTTPS, secret management, database migration policy, backup/restore monitoring, rate limit, CSRF strategy, server-side access control และการตรวจสอบไฟล์โดยบริการที่เหมาะสม
- ควรทดสอบกฎภาษี รูปแบบเอกสาร และการรับรองเอกสารกับผู้ทำบัญชี/กฎหมายของบริษัทก่อนใช้เป็นเอกสารทางการ

## โครงสร้างสำคัญ

- `src/app` หน้า App Router และ API routes
- `src/components` Workspace, ฟอร์ม และ UI กลาง
- `src/lib/catalog.ts` นิยามเมนู ฟิลด์ และสถานะ
- `src/lib/rules.ts` กฎคำนวณและ validation ที่ทดสอบได้
- `src/lib/service.ts` คำสั่งเขียนข้อมูล transaction และ audit
- `prisma/schema.prisma` schema SQLite
- `prisma/seed.ts` ข้อมูลสาธิตแบบ idempotent
- `tests` automated tests ของใบเสนอราคา คิวช่าง สต๊อก งวดชำระ ต้นทุน และ workflow เชื่อมโยง
